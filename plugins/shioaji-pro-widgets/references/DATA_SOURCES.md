# Data Sources — 選對來源，不要重複造輪子

Widget 每次要取資料前，**照這個順序選來源**，選到第一個能回答問題的就停。
跨來源混用同一個數字（例如同時拿 Shioaji 快照與 FinMind 收盤價講「今天漲幅」）
是本 plugin 最常見的錯誤，會產生對不起來的數字。

## 順序

| 順位 | 來源 | 什麼時候用 | 邊界 |
| --- | --- | --- | --- |
| 1 | **Shioaji Pro 原生 MCP tools** | 使用者自己的帳務、持倉、下單、版面、指標、回測、盤中報價 | 唯一能碰到「這位使用者」的來源 |
| 2 | **Shioaji API**（Python / CLI / HTTP） | Pro 沒有對應語意工具，但需要即時或歷史行情、法人、資券 | 需要已登入的 Shioaji session |
| 3 | **TPEx Open API** | 上櫃／興櫃市場的公開盤後統計，且 1、2 都拿不到 | **只有上櫃，沒有上市**；免驗證但無查詢參數、整包回傳、盤後日更。見 TPEX_OPENAPI.md |
| 4 | **FinMind**（免費版） | 較長期的歷史面板資料：月營收、財報、股利、法人、融資券 | 600 req/hour；**帶代號查單檔才免費**，撈全市場要付費等級。見 FINMIND.md |

## 硬規則

- **帳務與下單只能走順位 1。** 任何情況下都不要用公開資料推測使用者的持倉或損益。
- **一個問題只用一個來源算數字。** 需要跨來源時，明講哪個數字來自哪裡，並標註兩者的
  時間基準（盤中即時 vs 日結）。
- **公開資料是日結的。** TPEx 與 FinMind 幾乎都是收盤後才更新；盤中拿它們回答
  「現在多少」一定是錯的。
- **來源掛掉不要猜。** 明說某個來源取不到，回傳能拿到的部分，不要用記憶或推估補值。
- Widget 不自己存快取檔。需要重複讀的資料，在同一次對話內傳遞。
